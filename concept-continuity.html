02 / fragmentation

A 3D asset is not a file.

As assets move, they are copied, converted, optimized, renamed, repackaged, and modified.

Multiple files claim to represent the same asset. Dimensions evolve without coordination. Dependencies drift or break. Teams lose confidence in which state is authoritative.

identity absent / continuity interrupted

03 / canonical asset

It is a living composition.

One persistent identity. Source evidence that remains traceable. An evolving canonical state. Derived representations for downstream use.

persistent identity

The same asset throughout its lifetime.

Identity persists while asset state evolves.

source evidence / where it began

Origin remains traceable.

What was observed and what normalization decisions were made.

canonical state / what it is now

One evolving authoritative state.

Trusted normalization, composition, synchronization, and authoring operations may change that state without creating a new asset identity.

derived representations / downstream use

Outputs remain downstream.

Published files, optimized packages, previews, and platform-specific artifacts derive from canonical state.

Source evidence records where the asset began. Canonical state defines what the asset is now.

XYZO preserves continuity across all four.

06 / category position

A missing layer between specialized creation and downstream consumption.

Specialized tools should remain specialized. XYZO preserves how their outputs continue to belong to the same asset as they change.

Creation toolsGeometry, material, texture, animation, design intent.
Pipeline and production systemsTasks, approvals, schedules, versions, handoffs.
DAM, PIM, PLM, and MDM systemsStorage, cataloging, records, distribution.
Publishing systems and viewersTarget-specific delivery, presentation, visualization, review.

Pipelines move work. XYZO maintains the continuity and trusted state of the asset being moved.

It does not replace existing categories. It connects them around one trusted asset.
