# XYZO Design Language

## Purpose

The XYZO design language translates the brand and product principles into a consistent visual system.

It should make XYZO feel:

- precise
- considered
- technically credible
- visually resolved
- calm
- dimensional
- design-led
- modern without chasing trends

The website and product should feel related, but they should not be identical.

Forge is a professional working environment. The website is the clearest public expression of the product, its thesis, and its maturity.

Both should feel as though they belong to the same system.

---

## Core Visual Idea

XYZO preserves structure and trust while assets evolve.

The visual language should express the same balance:

- stable structure with changing content
- precision with movement
- technical depth with visual clarity
- dark working space with clear information surfaces
- restraint with moments of dimensional richness

The experience should feel resolved rather than decorated.

---

## Relationship Between Product and Website

The website should inherit the strongest qualities of Forge:

- a dark central workspace
- restrained neutral surfaces
- precise blue interaction cues
- clear object focus
- professional utility
- controlled transparency
- visible structure
- dimensional product content

It should improve upon Forge by introducing:

- stronger contrast
- more intentional typography
- cleaner hierarchy
- more disciplined spacing
- fewer washed-out gray surfaces
- clearer separation between information and interaction
- more refined use of color
- more deliberate motion
- a stronger sense of visual identity

The website should not reproduce the application interface as a page layout.

It should interpret the same visual principles at a more editorial and expressive level.

---

## Visual Character

The visual system should feel:

- architectural rather than decorative
- product-centered rather than campaign-centered
- dimensional rather than flat
- restrained rather than minimal for its own sake
- technical rather than futuristic
- refined rather than luxurious
- professional rather than corporate
- confident rather than loud

The desired impression is:

A sophisticated design tool and trusted asset system built with industrial-design judgment.

## Color System

The current Forge palette provides a useful foundation.

### Core Neutrals

#### Canvas Black

Use for the deepest product and media environments.

Suggested role:

- immersive product sections
- video and viewer backgrounds
- technical demonstrations
- high-contrast transitions

Reference value:

- `#0B0D0F`

#### Graphite

Use for primary dark surfaces.

Suggested role:

- dark page sections
- product frames
- diagrams
- navigation on dark backgrounds
- technical content surfaces

Reference values:

- `#1D2226`
- `#252B30`

#### Near White

Use as the primary light page surface.

Suggested role:

- editorial explanation
- long-form reading
- spacious transitions
- supporting content

Reference value:

- `#F7F8F8`

#### Soft Surface

Use for contained light panels and secondary information.

Reference value:

- `#EEF1F2`

#### Nardo Gray

Use selectively as a middle neutral.

Reference value:

- `#A0A4A6`

Nardo Gray should not dominate entire pages. Large amounts of middle gray reduce contrast and make the product feel unfinished.

### Text Colors

On light surfaces:

- primary text: `#0B0D0F`
- secondary text: `#4E565C`
- tertiary text: `#747C82`

On dark surfaces:

- primary text: `#F4F6F7`
- secondary text: `#B8C0C5`
- tertiary text: `#858E94`

Text must meet accessible contrast standards.

Do not use pale accent colors for long passages of text.

### Signal Blue

Signal Blue is the primary interaction and technical emphasis color.

Reference value:

- `#005AA2`

Use for:

- links
- active controls
- selection
- technical diagrams
- focus states
- precise emphasis
- primary calls to action when appropriate

Signal Blue should communicate action, selection, and system intelligence.

It should not become a general decorative wash.

### Validation Green

Validation Green represents trust, continuity, valid state, and XYZO identity.

Reference value:

- `#7FD1AE`

Use for:

- brand accents
- trusted or validated state
- key identity statements
- subtle lines and markers
- selective headline emphasis
- continuity diagrams

Validation Green should be used precisely.

Avoid large blocks of pale green text on mid-gray backgrounds. That combination weakens legibility and makes the color feel decorative rather than meaningful.

### Mist Blue

Reference value:

- `#A7C3D0`

Use for:

- subtle selected states
- quiet informational surfaces
- secondary diagrams
- controlled hover states
- low-intensity highlights

### Attention Orange

Reference value:

- `#E36F3F`

Use only for:

- warnings
- broken dependencies
- actions requiring attention
- destructive or irreversible operations

Orange is semantic, not decorative.

### Lavender

Reference value:

- `#B79BB6`

Lavender may be retained as a limited secondary data or diagram color.

It should not become a major brand color without a specific semantic role.

---

## Color Behavior

Color should communicate meaning.

Use:

- blue for interaction and selection
- green for trust, continuity, and valid state
- orange for attention and risk
- neutrals for structure and hierarchy

Avoid:

- gradients used only for atmosphere
- large pastel fields
- rainbow technical diagrams
- multiple competing accent colors
- glow around every interactive object
- color without semantic purpose

A page should usually have one dominant neutral environment and one primary accent behavior.

---

## Light and Dark Environments

XYZO should use both light and dark sections.

### Light Sections

Use for:

- foundational explanation
- long-form product logic
- category comparisons
- founder context
- readable supporting content

Light sections should feel open, calm, and editorial.

### Dark Sections

Use for:

- product demonstrations
- canonical asset visuals
- architecture diagrams
- interactive explanations
- videos
- moments of technical depth

Dark sections should feel immersive and precise, not theatrical.

### Transition Between Environments

Transitions should reinforce the narrative.

A useful pattern is:

- light surface for the problem
- dark surface for the product
- light surface for explanation
- dark surface for proof
- light surface for conclusion and action

Do not alternate backgrounds mechanically. Every transition should have a narrative purpose.

---

## Typography

Typography should feel professional, contemporary, and highly legible.

The current application use of Arial is functional but should not define the public brand.

### Primary Typeface Requirements

The primary typeface should be:

- sans serif
- structurally clean
- neutral but not anonymous
- readable at small sizes
- strong in large declarative headlines
- available across modern browsers
- appropriate for both design and technical contexts

Suitable directions include:

- Inter
- Geist
- Manrope
- IBM Plex Sans
- Neue Haas Grotesk or a licensed equivalent
- Helvetica Now or a licensed equivalent

The final choice should be tested in the actual site before becoming permanent.

### Monospace Typeface

Use a monospace face selectively for:

- file paths
- schema names
- technical labels
- identifiers
- code
- data readouts

Suitable directions include:

- IBM Plex Mono
- Geist Mono
- JetBrains Mono

Monospace should signal technical specificity, not become a decorative aesthetic.

### Type Hierarchy

#### Display

Use for major product statements.

Characteristics:

- large
- controlled
- compact line length
- confident weight
- deliberate wrapping

#### Section Headings

Use clear sentence-based headings rather than generic category labels.

Prefer:

“The canonical asset is the product foundation.”

Avoid:

“Platform Overview”

#### Body

Body copy should be comfortable to read and limited in width.

Recommended maximum line length:

- approximately 60 to 75 characters

#### Labels

Labels should be concise and visually quiet.

Use stronger weight or color only when labels carry semantic importance.

---

## Typography Behavior

Favor:

- sentence case
- controlled weight contrast
- generous line spacing
- strong but infrequent display statements
- readable body sizes
- left alignment for most content
- concise paragraphs

Avoid:

- all-caps paragraphs
- extreme weight variation
- oversized text without informational purpose
- centered body copy across long sections
- constant bold emphasis
- very light font weights on gray backgrounds
- decorative type effects

Typography should create hierarchy before boxes, borders, or color are added.

---

## Spacing and Proportion

Spacing should feel disciplined and generous.

The site should not feel empty, but every element should have room to resolve.

### Spacing Principles

- use a consistent spacing scale
- increase separation between conceptual sections
- keep related elements visually close
- avoid arbitrary padding values
- allow major statements to breathe
- preserve clear edges around product imagery
- use alignment as a primary organizational tool

### Recommended Spacing Scale

A practical base scale may include:

- 4
- 8
- 12
- 16
- 24
- 32
- 48
- 64
- 96
- 128 pixels

Values may scale responsively, but relationships should remain consistent.

### Content Width

Use different maximum widths for different content types:

- narrative copy: narrow
- diagrams: medium to wide
- product imagery: wide
- immersive demonstrations: full-width or near full-width

Do not force every section into the same centered column.

---

## Grid and Layout

The design should feel aligned and intentional.

Favor:

- strong vertical alignment
- asymmetric layouts when they improve hierarchy
- clear content anchors
- modular section construction
- wide product frames
- editorial text blocks
- diagrams integrated with copy
- responsive reflow rather than simple shrinking

Avoid:

- equal-sized card grids for every idea
- generic three-column SaaS layouts
- repetitive feature tiles
- excessive floating cards
- centered content by default
- layouts that exist only to fill space

The site should feel composed, not templated.

---

## Surfaces and Containers

Containers should be used when they clarify structure.

Favor:

- subtle borders
- low-contrast surface changes
- restrained corner radii
- clear containment
- occasional transparency over product imagery
- strong internal spacing

Avoid:

- every idea inside a card
- excessive shadows
- frosted-glass effects everywhere
- deeply layered panels
- soft inflated controls
- large rounded rectangles without purpose

### Corner Radius

The current application uses an 8-pixel radius effectively.

For the website:

- small controls: approximately 6 to 10 pixels
- panels: approximately 10 to 16 pixels
- large product frames: approximately 12 to 24 pixels

Avoid making every surface pill-shaped.

### Borders

Borders should be thin and precise.

Use them to:

- define hierarchy
- separate content
- indicate state
- reinforce diagrams

Avoid high-contrast borders around every component.

### Shadows

Shadows should be rare and subtle.

Prefer contrast, layering, and spatial separation over pronounced drop shadows.

---

## Transparency

Transparency can connect interface surfaces to the 3D content beneath them.

Use it selectively for:

- product overlays
- compact control surfaces
- explanatory annotations
- diagram layers

Transparency must preserve readability.

Avoid:

- large translucent text panels with low contrast
- transparency as a substitute for hierarchy
- stacking several translucent layers
- visual haze
- excessive blur

The Forge side panels demonstrate a useful relationship between interface and viewer, but their contrast should be improved for the website.

---

## Product Imagery

The product should be the strongest visual proof.

Use:

- real Forge screenshots
- close crops of meaningful interactions
- short screen recordings
- actual canonical package views
- synchronization states
- variant composition
- inspection details
- dependency and validation signals
- publishing outputs when functional

Do not rely on:

- generic stock 3D models without context
- decorative meshes
- random floating objects
- concept art presented as product
- invented interface mockups that imply unsupported functionality

Every product image should prove a specific claim.

---

## Product Framing

Forge screenshots should be presented with care.

Recommended treatments:

- clean browser-like or application framing
- controlled crop
- selective annotation
- restrained background
- enough resolution for text to remain credible
- emphasis on the relevant workflow

Avoid placing full desktop screenshots on the page without cropping or context.

Remove distracting operating-system chrome when it does not add credibility.

Do not hide product roughness through excessive effects. Improve the framing, not the evidence.

---

## 3D Asset Imagery

3D content should feel purposeful and professionally selected.

Favor assets that demonstrate:

- material richness
- recognizable scale
- geometry detail
- variants
- dependencies
- dimensional change
- downstream use

Industrial design, footwear, consumer products, furniture, equipment, and other designed objects are particularly appropriate because they connect naturally to XYZO’s design-led origin.

Avoid defaulting to:

- sci-fi helmets
- fantasy creatures
- gaming weapons
- generic robots
- neon abstract forms
- objects chosen only because they look futuristic

---

## Diagrams

Diagrams are central to explaining XYZO.

They should clarify:

- persistent identity
- source evidence
- canonical state
- evolving dimensions
- trusted dependencies
- synchronization
- derived representations
- category boundaries
- the operating loop

### Diagram Style

Favor:

- simple geometry
- strong alignment
- limited color
- consistent line weights
- clear direction
- concise labels
- visible authority relationships
- animation only when it improves understanding

Avoid:

- dense system maps
- decorative complexity
- tiny labels
- overlapping arrows
- excessive iconography
- different diagram styles on every page

### Authority Visualization

When visualizing the asset model, clearly distinguish:

- origin
- current authority
- runtime intent
- downstream output

Do not create diagrams that imply every artifact has equal authority.

---

## Icons

Icons should be simple, geometric, and consistent.

Favor:

- line icons
- controlled stroke weight
- recognizable forms
- restrained use
- functional meaning

Avoid:

- mixed icon libraries
- playful illustration icons
- emoji
- ornate pictograms
- icons used where a clear word is better

The current Forge icon style is directionally appropriate but should be standardized before becoming a formal brand system.

---

## Motion

Motion should communicate:

- evolution
- synchronization
- continuity
- composition
- state change
- movement between source, canonical asset, and output

Favor:

- slow controlled reveals
- purposeful transitions
- state changes
- content entering along meaningful paths
- before-and-after synchronization
- dimensional layers assembling
- subtle parallax when it reinforces depth

Avoid:

- constant ambient animation
- bouncing elements
- excessive scroll effects
- rapid text animation
- decorative particle fields
- spinning logos
- cinematic transitions that delay comprehension

Motion should explain the product before it entertains.

Respect reduced-motion preferences.

---

## Interaction

Interactions should feel precise and immediate.

Favor:

- clear hover states
- visible keyboard focus
- consistent button hierarchy
- responsive controls
- direct transitions
- obvious selected state
- useful feedback

Avoid:

- hidden navigation
- ambiguous click targets
- delayed response
- excessive hover transformation
- interactions that exist only for novelty

Signal Blue should be the primary interaction color.

Validation Green should indicate trust or confirmed state rather than general clickability.

---

## Calls to Action

Calls to action should feel calm and credible.

Primary actions may include:

- View the product
- Watch the demos
- Request a conversation
- Explore First Principles
- Request early access

Avoid aggressive conversion language.

Do not use:

- Get started now
- Transform your workflow
- Unlock the future
- Join the revolution

Primary buttons should be visually clear but not oversized or overdecorated.

---

## Navigation

Navigation should remain simple until the content requires complexity.

Possible top-level items:

- Product
- Principles
- Architecture
- Demos
- About
- Contact

Use audience-specific or protected material only when needed.

The navigation should not imply a mature platform with broad product lines that do not yet exist.

---

## Responsive Behavior

The mobile experience must be designed rather than reduced.

On smaller screens:

- preserve hierarchy
- shorten line lengths
- stack diagrams logically
- allow product media to remain legible
- simplify nonessential motion
- maintain comfortable touch targets
- avoid compressed technical labels
- preserve contrast and spacing

Do not shrink desktop diagrams until they become unreadable.

Create alternate mobile compositions where necessary.

---

## Accessibility

Accessibility is part of visual quality.

The design should include:

- sufficient contrast
- visible focus states
- semantic heading structure
- descriptive alternative text
- captions for video
- keyboard-operable interaction
- reduced-motion support
- readable minimum text sizes
- controls that do not rely on color alone

Pale green or gray text must not be used where it compromises readability.

---

## Current Visual Assets to Preserve

The following existing elements are worth carrying forward:

- the XYZO stacked wordmark
- graphite and near-black product environments
- Nardo Gray as a supporting neutral
- Signal Blue as an interaction cue
- Validation Green as a trust and identity cue
- dark 3D viewer space
- precise selection outlines
- professional utility
- restrained panel geometry
- the contrast between technical workspace and designed object

These elements should be refined rather than copied unchanged.

---

## Current Visual Traits to Improve

The following traits should not be treated as permanent brand decisions:

- Arial as the primary typeface
- large amounts of middle gray
- low-contrast text
- washed-out translucent panels
- pale green text on gray backgrounds
- utility controls that feel provisional
- equal visual weight across all interface regions
- deck layouts transferred directly into web pages
- excessive reliance on centered text
- limited distinction between narrative and product evidence

---

## Visual Directions to Avoid

Do not build the XYZO website around:

- cyberpunk aesthetics
- gamer interfaces
- neon lighting
- constant glow
- generic dark-mode SaaS design
- heavy enterprise dashboards
- glassmorphism as a primary style
- excessive gradients
- random wireframe objects
- decorative node graphs
- futuristic imagery unrelated to the product
- visual density modeled after Omniverse
- interface complexity inherited from legacy CAD tools
- playful community-tool styling
- spectacle associated with game-engine marketing

XYZO should feel technologically advanced because the product is advanced, not because the page looks like science fiction.

---

## Design Decision Test

A design decision is aligned when it:

- improves clarity
- reinforces hierarchy
- makes product evidence more credible
- communicates identity or state
- supports the narrative
- feels intentional
- respects creative work
- reduces visual noise
- remains legible
- reflects the product’s precision

A design decision is misaligned when it:

- decorates without meaning
- weakens contrast
- hides the product
- imitates a trend
- makes the site feel generic
- overstates product maturity
- introduces unnecessary complexity
- sacrifices usability for visual effect
- confuses canonical authority with downstream representation

---

## Final Standard

The XYZO design language should feel like the visual expression of a trusted 3D asset system.

It should combine the precision of a professional industrial-design tool, the ambition of connected 3D infrastructure, and the restraint of a product built with clear design judgment.

The result should feel clean, dimensional, technically credible, and fully considered.
